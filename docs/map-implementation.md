## Соединения и ввод

`assets/js/countries-map.js` строит линии только при `min-width: 1181px`. Координаты берутся из фактических DOM-прямоугольников и переводятся в систему SVG через обратную матрицу `getScreenCTM()`. Предусмотрены зазоры 6 px после карточки и 9 px перед логотипом. У Ирана две точки назначения.

Состояния наведения и клавиатурного фокуса разделены. В сценарии «фокус на Иране → мышь над Египтом → уход мыши» восстанавливается реальный фокус Ирана. На touch наведение не фиксируется; выбор карточки сохраняет подсветку ее логотипов, но в компоновке до 1180 px линии скрыты.

Геометрия обновляется через `ResizeObserver`, события resize/scroll, `visualViewport`, загрузку шрифтов и изображений. Для геометрических переходов предусмотрен ограниченный по времени rAF, без постоянного цикла в покое. SVG-пути переиспользуются, обработчики и наблюдатели снимаются при уничтожении экземпляра.

Эти свойства подтверждены приемкой 09.11: все восемь логотипов присутствуют на 900/901 и 1180/1181 px, нормализованные центры не меняются, все описания видны. Проверены обычное и reduced-motion поведение, смешанный ввод и resize без перезагрузки. Максимальная ошибка концов линий в 135 измерениях составила 0.005005 px при неизмененном допуске 1 px.

## Причины исправлений и их границы

В попытке 06.11 локальные якоря логотипов были связаны с картой, но общий surface имел `left: 10%`, `width: 90%` и постоянный `top: 55px`. Это сдвигало всю географию относительно клиентского эталона. Проверка одних локальных процентов такой дефект не обнаруживала.

Релиз 07.11 исправил масштаб и кадрирование surface по береговой линии. Однако легенда сохраняла фиксированные размеры и раскрытие при hover/focus, а мобильная ветка до 900 px скрывала все восемь логотипов. Полная композиция поэтому не совпадала с эталоном.

Свежий аудит 09.11 также подтвердил устаревание концов SVG-линий при переходах между карточками и потерю активной страны после смешанного ввода. Самостоятельный дрейф нормализованных якорей по присланным изображениям не подтвержден. Версия 09.11 меняет компоновку легенды и механику соединений, но сохраняет исходный PNG, изображения логотипов и все восемь наборов координат.

Утвержденные новости, CMS клиента и другие разделы в это исправление не входят.

## Независимая регистрация береговой линии

Исходный PNG совмещен с новым эталоном по 5198 точкам границы альфа-канала карты. Области легенды и восьми белых карточек логотипов исключены из регистрации. Масштаб и сдвиг определены по береговой линии, а не подогнаны по координатам логотипов. Используется один масштаб по двум осям, без растяжения, поворота или деформации.

Измеренное преобразование из пикселей native PNG в пиксели эталона 2048 × 1302:

```text
referenceX = nativeX × 0.9481910 - 92.5152
referenceY = nativeY × 0.9481910 + 21.2921
```

Для реализации выбрано близкое рациональное преобразование:

```text
scale = 2048 / 2160 = 0.948148148...
referenceX = nativeX × scale - 92.444444
referenceY = nativeY × scale + 21.333333
```

На ширине 2048 полный PNG занимает примерно `x = -92.4444`, `y = 21.3333`, `width = 2258.4889`, `height = 1632.7111`. Карта намеренно выходит за границы секции 2048 × 1302, как в эталоне; это не означает, что весь native PNG должен быть виден без кадрирования.

Текущие CSS-параметры общего слоя:

```css
.countries-map__viewport {
  width: 100%;
  aspect-ratio: 2048 / 1302;
}

.countries-map__surface {
  top: 1.638505889%;
  left: -4.513889%;
  width: 110.277778%;
  aspect-ratio: 2382 / 1722;
}
```

Вертикальный процент теперь считается от высоты отдельного viewport, а не от полной секции с легендой. При ширине 2048 px он дает прежний зарегистрированный сдвиг 21.3333 px. Во всех компоновках карта использует одну пропорцию и одну систему координат, независимо от высоты окна и переносов текста.

В боковой компоновке заголовок и легенда начинаются на 5.56640625% ширины секции, то есть x = 114 px на эталоне 2048. Верх легенды равен 152 px, ширина 292 px при этой ширине; для читаемости задан минимум 232 px. Секция может стать выше карты из-за текстовых минимальных размеров. До 1180 px легенда находится в потоке ниже viewport, поэтому ее текст не перекрывает логотипы. Отдельной смены DOM или координат на 900/901 px нет.

Исторически в релизе 07.11 использовались `min-height: max(900px, 63.57421875vw)`, `top: 1.041667vw` у surface и ограниченный общий layout-отступ легенды. Эти правила заменены версией 09.11; их не нужно переносить вместе с новой разметкой.

Тогда использовалось уменьшенное изображение «Дизайн» 829 × 464, inline object `kix.5oa4slvny3g0`; исходный статический handoff имел commit `a26d24dbf9383e56412f28bff8ae6665eedb00d8`, native карта - Git blob `925bac886e3a2309fa95910ab0fafeba62764871`.

По тому изображению восстановили относительные якоря восьми логотипов, но оставили прежние размер, сдвиг и ограничение высоты всей карты. Автоматическая проверка этих якорей не обнаружила ошибку общей композиции. Новый клиентский PNG 2048 × 1302 и независимая регистрация береговой линии устраняют этот пробел в методике. Старый уменьшенный target больше не является основным критерием приемки.

Остальные замечания старого документа, изменения CMS и редизайн других разделов в это исправление не входят.
