## Причина ошибки и границы исправления

В предыдущей версии логотипы и изображение карты были правильно связаны одной системой координат `.countries-map__surface`, но сам surface отображался с `left: 10%`, `width: 90%` и постоянным `top: 55px`. Это уменьшало и сдвигало всю географию вместе с логотипами относительно эталона. Правильные локальные проценты внутри неправильно размещенного surface не дают правильной композиции секции.

Прежние тесты сопоставляли нормализованные координаты логотипов с такими же константами `MAP_TARGET`. Они проверяли относительное положение внутри surface, загрузку, отсутствие пересечений и интерактивность, но не сопоставляли трансформацию самого surface с клиентским изображением. Поэтому их успешный результат нельзя считать подтверждением визуального совпадения карты с макетом.

В `assets/css/styles.css` исправлены общий масштаб и сдвиг surface, высота секции и защитный предел левого отступа легенды на сверхшироких экранах. Отдельные восемь наборов `top`, `left`, `width` логотипов не меняются. PNG карты и логотипов также не меняются.

Шрифты, ширина и поведение карточек стран, их раскрытие при hover/focus, мобильная версия и блок новостей не изменены. Скрипт `assets/js/countries-map.js` не меняется: соединения строятся по фактическим `getBoundingClientRect()` карточек и логотипов. У Ирана сохраняются две отдельные точки назначения.

## Независимая регистрация береговой линии

Исходный PNG совмещен с новым эталоном по 5198 точкам границы альфа-канала карты. Области легенды и восьми белых карточек логотипов исключены из регистрации. Масштаб и сдвиг определены по береговой линии, а не подогнаны по координатам логотипов. Используется один масштаб по двум осям, без растяжения, поворота или деформации.

Измеренное преобразование из пикселей native PNG в пиксели эталона 2048 × 1302:

```text
referenceX = nativeX × 0.9481910 - 92.5152
referenceY = nativeY × 0.9481910 + 21.2921
```

Для реализации выбрано близкое рациональное преобразование:

```text
scale = 2048 / 2160 = 0.948148148...
referenceX = nativeX × scale - 92.444444
referenceY = nativeY × scale + 21.333333
```

На ширине 2048 полный PNG занимает примерно `x = -92.4444`, `y = 21.3333`, `width = 2258.4889`, `height = 1632.7111`. Карта намеренно выходит за границы секции 2048 × 1302, как в эталоне; это не означает, что весь native PNG должен быть виден без кадрирования.

CSS-параметры общего слоя:

```css
.countries-map {
  min-height: max(900px, 63.57421875vw);
}

.countries-map__surface {
  top: 1.041667vw;
  left: -4.513889%;
  width: 110.277778%;
  aspect-ratio: 2382 / 1722;
}
```

Вертикальный сдвиг задан от ширины viewport, а не от высоты секции: минимальная высота 900 px иначе внесла бы ошибку на узких desktop-экранах. Новый `min-height` сохраняет 900 px на ширинах 901/1024 и дает ровно 1302 px на ширине 2048. Прежний максимум 1132 px дополнительно обрезал секцию на 170 px при этой ширине.

Существующий левый отступ заголовка и карточек ограничен только для сверхшироких экранов:

```css
@media (min-width: 901px) {
  .countries-map__title,
  .countries-map__cards {
    left: min(max(var(--layout-pad), calc((100vw - var(--layout-max)) / 2)), 15vw);
  }
}
```

Этот предел не меняет отступы на 901/1024/1440/1920/2048 и начинает действовать примерно после 2057 px. На 2560 он дает 384 px вместо прежних 560 px и не позволяет легенде наезжать на географически привязанные логотипы. Это защита адаптива, не изменение типографики или поведения легенды.

## Выполненная проверка

Отчет: `20261107T050457Z-4114974/report.json`, SHA-256 `31d9382ee4978425f723a268e37dde55fe6e164533213028c9b38c5f9ad0b9b8`. При упаковке он включается как `qa/report.json` с удалением серверных абсолютных путей.

- Проверены SHA-256 и натуральные размеры исходной карты, загрузка восьми PNG логотипов, неизменность скрипта соединений и файлов утвержденной новости. Сохранены 29 контрольных сумм исходников до запуска QA.
- На ширинах 901, 1024, 1440, 1920, 2048 и 2560 проверены абсолютные границы секции, surface и native PNG, измеренные прямоугольники восьми логотипов и проекция трех независимых географических ориентиров. Нет горизонтального overflow, пересечений логотипов между собой или с легендой.
- Максимальное отклонение проверяемых координат/размеров от растровых измерений на ширине 2048: 1.328125 px в Chromium/WebKit, 1.333313 px в Firefox. На ширине 2560 максимум 1.671875 px. DOM-высота секции 2048 равна 1302 px; захваченный PNG может быть на один пиксель выше из-за округления дробной позиции clip.
- На 901 и 2560 проверено активное увеличение Беларуси без пересечений. Проверены hover Ирана, клавиатурный переход Египет → Иран → Китай, две линии у Ирана и очистка линий после blur. При активном Иране проверен resize 901 → 1024 → 901 без повторной фокусировки и фактические конечные точки обеих SVG-линий.
- Повторно проверен утвержденный попап на 1440×1000, 1280×800, 390×844 и 320×740: текст, фотографии, источник, клавиатура, закрытие, прокрутка и восстановление положения страницы. Во всех трех браузерах отсутствуют ошибки JavaScript и локальных ресурсов.
- Основной агент просмотрел скриншоты карты 2048 и 1440, активной Беларуси 901 и 2560, а также утвержденной новости. Береговая линия и восемь логотипов визуально сопоставлены с новым эталоном. Существующие стили и раскрытие карточек стран сохранены; полное попиксельное совпадение всей секции не заявляется.

Pure-контракт отдельно проверен на реальном отчете 06.11.2026: все 12 старых map-кейсов отклонены новой независимой проверкой. Географические контрольные точки в браузерном тесте проектируются из DOM-прямоугольника подтвержденного SHA исходного PNG; это не автоматическое сравнение пикселей скриншотов. Физические Safari/iOS не тестировались.

Публикация и новый комплект фиксируются отдельно в `CHECKPOINT.md`. Старый архив с прежним CSS не является актуальным комплектом этого исправления.

## История предыдущей попытки

Исходное замечание находилось в [«Комментарии по сайту | АСЕ»](https://docs.google.com/document/d/1iUsqmLMdtUdEDmdtp2dnonSeBH0HlLBJdiXKCODCD8k/edit?tab=t.0), раздел «Страны участники». Тогда использовалось уменьшенное изображение «Дизайн» 829 × 464, inline object `kix.5oa4slvny3g0`; исходный статический handoff имел commit `a26d24dbf9383e56412f28bff8ae6665eedb00d8`, native карта - Git blob `925bac886e3a2309fa95910ab0fafeba62764871`.

По тому изображению восстановили относительные якоря восьми логотипов, но оставили прежние размер, сдвиг и ограничение высоты всей карты. Автоматическая проверка этих якорей не обнаружила ошибку общей композиции. Новый клиентский PNG 2048 × 1302 и независимая регистрация береговой линии устраняют этот пробел в методике. Старый уменьшенный target больше не является основным критерием приемки.

Остальные замечания старого документа, изменения CMS и редизайн других разделов в это исправление не входят.
