## Подключение других новостей

1. Добавьте `template` с уникальным ID `news-<slug>` по структуре `news-spief-2025`.
2. На ссылке карточки укажите `data-news-open="<slug>"`, `aria-haspopup="dialog"` и `aria-controls="news-dialog"`.
3. Сохраните реальный `href` источника: это рабочая ссылка без JavaScript и для открытия через Ctrl/Cmd.
4. Добавьте `data-news-card` на карточку, если нужно открытие кликом по обложке или заголовку.

В шаблоне должны оставаться заголовок `id="news-dialog-title" data-news-title tabindex="-1"`, текстовая колонка `data-news-body` и ссылка `data-news-source`.
Не выводите непроверенный HTML из внешнего API. Контент CMS должен проходить штатную очистку на стороне сервера.
Текст может быть любой длины; высота окна ограничена только viewport, внутри прокручивается вся статья.
Изображение в теле необязательное: удалите или добавьте `figure.news-article__figure--inline`, не меняя JavaScript.

Программное открытие: `window.ACENews.open('spief-2025', triggerElement)`; закрытие: `window.ACENews.close()`.
Метод `open` возвращает `false`, если шаблон отсутствует или браузер не поддерживает нативный `dialog`; внешняя ссылка остается доступной.

## Поведение и проверка

Попап открывается поверх страницы; фон становится недоступен для фокуса и прокрутки.
Закрытие: крестик, Esc, клик именно по фону. Клик внутри статьи не закрывает окно.
После закрытия возвращаются фокус на исходную ссылку и прежнее положение страницы. Шаблон не добавляет записи в историю браузера.
Для клавиатуры доступны чтение, прокрутка, источник и закрытие; Tab не уходит на страницу под модальным окном.

Карта исправляется по полному клиентскому изображению `desctop (1).png`, 2048 × 1302. Причиной были неверные масштаб и смещение общего слоя карты. Его новое положение независимо определено по береговой линии; отдельные восемь якорей, изображения логотипов и утвержденная новость не изменяются.
Новый QA проверяет абсолютное положение карты и логотипов относительно секции, а не только проценты внутри общего слоя. Измерения и SHA-256 эталона записаны в `docs/map-reference-20261107.json`; методика описана в `docs/map-implementation.md`. Новый контракт отвергает сохраненную геометрию всех 12 старых map-кейсов от 06.11.2026, хотя прежние тесты считали их успешными.
Повторный прогон 07.11.2026: **39 из 39 сценариев прошли** в Chromium 145.0.7632.6, Firefox 146.0.1 и WebKit 26.0. Проверены карта на ширинах 901, 1024, 1440, 1920, 2048 и 2560, активное увеличение логотипа Беларуси и сохранение двух соединений Ирана при изменении ширины. Регрессия новости проверяет экраны 1440×1000, 1280×800, 390×844 и 320×740, полный текст, изображения, клавиатуру, закрытие и восстановление положения страницы. Ошибок JavaScript и загрузки локальных ресурсов нет.
На ширине эталона 2048 px максимальное отклонение проверяемых координат и размеров от измерений скриншота составило 1.34 px. Дополнительно просмотрены скриншоты карт 2048/1440, активной Беларуси 901/2560 и утвержденной новости. Это проверка геометрии карты и логотипов, не заявление о полном попиксельном совпадении всех элементов страницы: существующие карточки стран и их раскрытие сохранены.

`scripts/verify-handoff.cjs` позволяет повторить проверки последовательно на локальном сервере, не отправляя формы и не вызывая API клиента. Сборщик комплекта прикладывает отчет и выбранные скриншоты в `qa/`.
Физические устройства с Safari/iOS не тестировались: проверка Playwright WebKit не заменяет проверку приложения Safari.

`news-preview.html` генерируется из канонического `index.html`. После изменения текста:

```sh
node scripts/build-news-preview.cjs
```

## Комплект для передачи

Комплект этого исправления основан на новом успешном QA от 07.11.2026 и визуальном просмотре скриншотов. Архив от 06.11.2026 содержит прежнюю геометрию карты и для передачи этого исправления не подходит.

Выходной файл: `artifacts/handoff/ACE-Верстка.zip`. В комплект входят исходная верстка, документация, `manifest.json`, отчет `qa/report.json`, контрольные суммы `qa/code-proof.json` и пять выбранных скриншотов, включая карту шириной 2048 px. Сборщик проверяет точный состав, ZIP CRC, полную распаковку и SHA-256 каждого файла. Он не заменяет существующий архив без предварительного сохранения старого комплекта.
